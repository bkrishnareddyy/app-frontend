## Cross-cutting Quality Standards violations found

Checked against the 10 rules in `project-plan.md`'s "Quality Standards for Every Agent" section, scoped to what F11/F12 code touches (not a full-repo audit):

1. **No fake data** — Violated in `src/app/api/audit/export/route.ts:84-85` (fabricated Vercel Blob URL, see F12-E-3 above). The DPS screening path (`dpsScreening.ts`, `demo/screening/dps/route.ts`) is a good counter-example of doing this *correctly* — honest `INDETERMINATE`/503 instead of a fake clearance.
2. **Decimal.js for money** — Only 11 files under `src/lib`/`src/modules` reference `decimal.js`/`Decimal`. Not exhaustively checked whether every money field in F11/F12-touched code (e.g. `dutyPerEntry` in dashboard metrics) round-trips through Decimal before serialization — `metrics/route.ts:37` does `Number(s.dutyPerEntry)`, which is a `Decimal → Number` cast for display, arguably fine for a rounded display value but worth a second look.
3. **Tenant isolation (`accountId` on every query)** — Spot-checked routes all include `accountId: ctx.accountId`; dedicated tenant-isolation test files exist (`product-tenant-isolation.test.ts`, `party-tenant-isolation.test.ts`, `tenant-isolation-routes.test.ts`, `multi-tenant.test.ts`). No violation found in sampled code, but F12-A-2's missing DataMode middleware means tenant isolation *by account* is likely fine while isolation *by data mode within an account* is not enforced at all.
4. **One Vitest test per capability** — Broadly satisfied; `tests/` has ~20+ files directly named after F11/F12 capabilities. Dashboard (F12-D) and API-key management (F12-F) appear to be the exceptions with no dedicated test file found.
5. **AuditLog on every write** — 65 route files call `createAuditLog(`. Given 146 mutation route files total, this is a lower ratio than 1:1, though not every mutation is "domain data" (some are read-shaped POSTs like `/match` endpoints, which correctly don't audit-log). Not a clean pass/fail without per-route triage.
6. **OpenAPI `.describe()` on every Zod schema** — **Zero occurrences.** `grep -rln "\.describe(" src --include="*.ts"` returns nothing anywhere in the codebase. This standard is entirely unimplemented, not just under-implemented, across all of F11/F12 (and apparently the whole app). Since the plan states this is "the source of truth for the chat tool definitions," this may also be quietly breaking or limiting F13's chat tool surface.
7. **No `any` types** — Not zero: `grep -rn ": any\b|<any>|as any\b" src` returns 25 hits, including `CommandCenterClient.tsx:119` (`useState<any>(null)` for the dashboard metrics payload cited above in F12-D-1).

None of the F11/F12-specific routes audited here (products, parties, webhooks, agent-policies, dashboard) implement it. This standard is essentially unaddressed outside the filing/drawback domain.

No violation found in the models reviewed.

No stray `TODO`/`FIXME` markers were found in F11/F12 territory — the only 3 in the whole `src` tree are in `src/lib/filing/transmissionProvider.ts` (CBP ABI transmission, an F07 concern, and one that's honestly commented rather than silently faked).

## Top 5 fixes ranked by severity

1. **F12-A-2 — Build the missing `DataMode` Prisma middleware.** `src/lib/db.ts` is 19 lines with zero query interception. This is the task the capability header names as the primary hardening gap, and it is simply not there. Every DEMO/PRODUCTION-scoped query in the app currently depends on a developer remembering a manual `where: { dataMode: ... }` clause — exactly the failure mode the task exists to eliminate. This is a data-leak risk, not a cosmetic gap.

2. **F12-F-3 — Wire up webhook delivery, or stop advertising it.** `deliverWebhookEvent()` in `src/lib/webhooks/deliver.ts` is fully implemented (HMAC signing, retry-ready structure, delivery logging) but has zero callers. `inngest` is an installed, unused dependency. Right now, a customer who registers a webhook via the UI-ready `POST /api/admin/settings/webhooks` will never receive a single event — the feature looks complete from the API surface but does nothing end-to-end.

3. **F12-B-4 — Close the permission-gate gap on 66 of 146 mutation routes.** The capability's own stated starting problem ("many routes don't check specific permissions") is still true for 45% of mutation endpoints, including consequential ones: `POST /api/decisions`, `POST /api/decisions/bulk`, `POST /api/shipments`, `POST /api/filing`, `POST /api/compliance/audits/run`. `permission.catalogue.ts` and the `withAuthenticatedRoute({ permission })` mechanism both exist and work correctly where used — this is a rollout gap, not a design gap, which makes it cheap to fix systematically.

4. **F12-E-3 — Remove the fabricated Vercel Blob URL from the compliance export route.** `src/app/api/audit/export/route.ts` returns a `downloadUrl` that points nowhere (`vercel-blob.qubere.ai/...?token=exp_24h_val_...`) and the code comment admits it's a "simulated mockup." This is a direct violation of the #1 global quality rule ("No fake data, ever") in a route whose entire purpose is producing a legally-relevant compliance record for a departing broker relationship. It also has no UI entry point, so it's currently unreachable by any real user anyway — either finish it (real Blob upload) or pull it until it's real.

5. **F12-D-3/D-4 — Dashboard is missing both required charts.** The cycle-time timeline (30-day rolling median) and exception age-bucket bar chart from the spec don't exist; the dashboard shows single scalar tiles instead. The underlying data is already computed and returned by `/api/dashboard/metrics` (up to 6 snapshots), so this is a front-end-only gap — lower severity than 1-4 above because no data integrity or security risk is involved, but it's a visible, easily-demoed gap between the plan and the product.

Honorable mention: F11 is in genuinely good shape — Capability A and B in particular show real engineering care (the `normalizationEngine.ts` file's own doc comment reads like someone who fixed exactly this problem and documented why; the DPS screening honestly refuses to fake a clearance on an empty watchlist). F12 is where the gap between "plan" and "shipped" is concentrated, particularly around the newer/harder capabilities (D dashboard, E knowledge retention, F ERP groundwork) that were likely built last and under time pressure.
