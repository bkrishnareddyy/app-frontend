## Top 5 fixes ranked by severity

1. **Real HTS rates in money-calculation paths, not "2.8%" placeholders.** `src/lib/tariff/landedCost.ts:56` and `src/modules/drawback/drawback.service.ts:47` both fabricate a flat duty rate instead of looking up the line item's actual HTS rate via `loadHtsCodesMap`/`parsePublishedDutyRate` (which already exist and are used correctly elsewhere, e.g. `filing/[id]/entry-summary/route.ts`). This directly produces wrong dollar amounts in landed-cost simulations and drawback claims — the single highest-impact, most-fake-data-facing bug found.
2. **`triageState` is written but never read.** Every reader (`workQueueLoader.ts:43`, `ActionsClient.categorize`, `DocumentReviewPanel.classifyDecision`) still filters/categorizes off the legacy `status` string via `triageDecision()`/`actionableStatusVariants()`. The column, its index, and 8 agent-writer call sites are dead weight relative to what actually drives the UI. Either wire the readers to `triageState` or remove the column and its misleading "readers never parse prose" schema comment.
3. **OpenAPI spec covers ~3% of routes and no route schema has `.describe()`.** `scripts/generate-openapi.ts` hand-registers 7 endpoints against 206 real routes, disconnected from the actual Zod schemas in route files. Per the AI-assistant memory note ("real API gaps found (no filters/aggregates/team-roster endpoint yet)"), this spec is the thing the chat tool-calling interface depends on — it is currently fiction for 97% of the API surface.
4. **`AgentPolicyConfig` per-account thresholds are a UI dead end.** A compliance officer can edit auto-approval thresholds in `src/app/api/admin/settings/agent-policies/route.ts` and the change has no effect — `applyAutoApprovalPolicy()` never reads that table, only its own hardcoded 85/60 constants. This is a silent trust-breaking bug: the settings page implies control that doesn't exist.
5. **No CI pipeline exists at all.** Not just "openapi generation isn't in CI" — there is no `.github/workflows` or equivalent anywhere, so none of F01's guarantees (tests passing, lint, `npm run openapi` not erroring) are enforced on any push or PR. Everything verified in this audit was verified by hand; nothing stops a regression from merging silently.
